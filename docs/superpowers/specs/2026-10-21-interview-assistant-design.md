# Qt 线上面试辅助与复盘工具设计

日期：2026-10-21

状态：已按用户确认的 C++ / Qt Widgets 方向实现；验证进度见 `docs/acceptance.md`。

## 1. 目标与已确认需求

用户需要 Windows 上的 Qt 桌面软件，用于线上面试：实时记录双方对话，提取面试官问题，可选择调用 OpenAI GPT 或 DeepSeek 分析并显示参考回答，面试结束后复盘并提出改进建议。用户已明确要求回答服务可选。

成功标准是：能采集并保存双方声音，转写可追溯到时间位置；问题和追问可人工修正；回答逐步显示且不阻塞界面；复盘能引用本次实际对话。录音和实时 AI 辅助在获得参与者同意的场景下使用。

## 2. 技术选择

比较三种实现方式：

| 方式 | 优点 | 代价 |
| --- | --- | --- |
| C++ / Qt Widgets，推荐 | 原生桌面集成；便于实现 WASAPI；本机已有 Qt 套件目录 | 音频和网络状态管理需认真实现 |
| Python / PySide6 | 原型开发较快 | 需要额外音频依赖与 Python 打包环境 |
| Qt 界面 + Python 服务 | 方便使用 Python 语音生态 | 第一版多进程通信与部署成本较高 |

选择 C++ / Qt 6、CMake、Qt Widgets、Qt Multimedia、Qt Network、Qt SQL / SQLite；Windows 播放音频使用 WASAPI loopback，麦克风使用 QAudioSource；实时转写采用 Windows WinHTTP WebSocket，省去额外 Qt WebSockets 组件。

现场发现 D:/Qt/6.11.2 下有 mingw_64 和 msvc2022_64 目录，D:/Qt/Tools 下有 CMake、Ninja、MinGW 工具目录；已确认 MinGW 套件的 qmake、Qt Multimedia 配置文件及配套工具可执行文件存在。当前未找到该套件的 Qt6WebSocketsConfig.cmake，实时转写阶段需要先补齐此组件并经 CMake 验证。优先使用 Qt 配套的 MinGW，避免误用 PATH 上其他项目的编译器。此记录不等于编译或设备运行已经验证。

## 3. 第一版范围

包括：会话创建与历史记录、音频设备选择与电平、开始/暂停/结束、双路录音、实时中文转写、问题列表、自动提问检测与手动提取、OpenAI / DeepSeek 可选的流式参考回答、人工编辑问题、复盘报告、Markdown 导出、API 设置。

第一版以中文、单个应聘者和一条远端音频来源为目标。可填写目标岗位与项目经历摘要以约束答案；PDF 简历解析、多位面试官声纹识别、屏幕识别和代码执行留到后续。

## 4. 界面与基本操作

- 顶部：会话名称、岗位、开始/暂停/结束、录音状态、网络状态、运行时长。
- 左侧：带来源与时间戳的对话流；临时转写与最终转写有区别；允许修正文案。
- 中间：按时间排列的问题和追问；支持编辑、合并、手动新增和重新分析。
- 右侧：当前问题、简短回答要点、详细解释、示例与可能的追问；支持停止生成；显示生成该答案的服务商和模型。
- 独立历史与复盘页面：选取会话、回听录音、查看复盘、导出和删除。
- 设置：音频设备、独立的转写服务配置；文本服务下拉选择 OpenAI 或 DeepSeek，各自保存模型名称、API 地址与凭据；提供连接测试。主窗口显示当前文本服务并允许切换，设置在下次请求开始时生效。

结束会话时先停止采集并完成落盘，处理有界等待内的最终转写，再允许生成复盘。未完成的记录明确标注，历史会话可重新请求复盘。

## 5. 音频采集与转写

分别采集“远端播放音频”和“我的麦克风”，使用统一单调时钟记录两路起点与片段位置，便于回放和关联。音频采集在工作线程执行，网络使用异步信号，主线程只更新界面。

WASAPI loopback 捕获所选输出设备的播放混音，可能包含通知和其他应用声音；第一版不保证只录到会议应用。推荐佩戴耳机以减少远端声音再次进入麦克风。来源标签代表音频通道，不能当作可靠的个人身份识别。

采集设备的原生格式先转换为转写接口要求的 PCM 格式，再按小块提交；声道数、采样率与重采样遵循所选服务接口。两路独立送转写并分别保存最终文本及服务端片段标识。

转写文本包含会话、片段、通道、开始/结束时间、临时/最终状态与修订版本。时间位置由应用的采集时钟和音频提交区间关联，并标记为近似片段位置；当前实时转写模型不提供逐词时间戳，不能把应用估算位置描述为服务端精确对齐。临时文本仅用于显示；问题提取主要处理最终文本，防止对尚未说完的话反复生成答案。

音频文件存于本地会话目录，默认保留两路 WAV；SQLite 记录相对文件位置。暂停后停止采集与上传并记录暂停区间，恢复时创建新的音频段。界面说明音频会发送至所配置转写服务，问题与上下文会发送至文本服务。

## 6. 问题提取与参考回答

远端最终文本进入提取队列，结合最近上下文判断提问、背景陈述及追问。合并紧邻的相关片段，遇到明确问题结束或达到缓冲时限后提交，避免无限等待。提供“立即提取”和手动输入以处理漏检。

提取结果包含原文片段引用、规范化问题、问题类型、追问关联及是否需要澄清；结构化结果先校验再保存。对相同来源片段和相同规范化问题去重；文本修订后保留版本关系，用户可重新分析。

回答使用当前问题、必要对话上下文及用户填写的岗位和经历摘要；先给可快速阅读的要点，再补充解释和示例。个人经历不足时给出可填写的表达框架，不虚构用户做过的项目或技术成果。

问题提取和回答生成分开调用，第一版共用当前选定的文本服务配置；复盘也默认使用该配置，可在生成前切换。语音转写独立配置，选择 DeepSeek 回答不改变现有转写连接。

实现统一的文本服务接口，并为两家提供独立适配器：

| 文本服务 | 第一版调用方式 | 流式结果处理 |
| --- | --- | --- |
| OpenAI GPT | Responses API | 解析语义 SSE 事件和终止状态 |
| DeepSeek | 官方 Chat Completions API，默认地址 https://api.deepseek.com | 解析 choices[].delta.content，处理结束原因及 [DONE] |

两家都逐步显示最终答案文本。模型名称可配置，不将当前模型别名写死为永久有效。DeepSeek 问题提取使用 JSON Output，并在客户端校验字段和来源引用；空结果、截断或不合结构的响应显示可重试错误，不落成有效问题。不同接口的思考字段不作为参考答案正文显示。

每次请求开始时固定服务商、API 地址、模型和对应凭据，关联独立请求 ID、问题 ID 及问题版本。切换服务只影响后续请求，当前请求继续使用原配置，也可由用户取消；历史答案保留原始来源，失败不会自动切换到另一家服务。API 地址和模型可配置，但不承诺任意“兼容接口”都支持转写、Responses 或相同事件格式。

第一版每路转写保持独立会话，问题提取串行，自动回答同一时间只执行一个。出现新问题时，旧请求可由用户停止，新问题先入队；转写持续运行，不等待文本模型生成。

## 7. 面试后复盘

按对话顺序关联每个问题、追问和用户实际回答，生成：

1. 问题及考察知识点。
2. 实际回答中正确的部分、遗漏与可能的错误。
3. 更清晰的表达示例及补充知识。
4. 后续练习清单，按本次暴露的问题排序。

报告引用实际转写片段与时间戳，AI 参考答案单独标记，禁止作为用户已经回答的内容。转写缺失或角色关联不清时标注证据不足，不推断面试官的录用意向。长会话按问题分段处理后汇总，避免无界上下文请求。

## 8. 数据和凭据

主要实体为 Session、AudioSegment、TranscriptSegment、Question、Answer、Review；实体具有稳定 ID，问题提取结果、答案和复盘保存对应来源版本、服务商及模型标识。音频落文件，文本、状态与时间位置存 SQLite。

用户数据默认位于 QStandardPaths 的应用数据目录下，界面可显示实际路径。导出 Markdown 包含对话、问题、参考答案和复盘，不包含凭据。

API Key 由用户在本机设置页填写，保存到 Windows 凭据管理器；源码、SQLite、导出和日志不保存明文 Key。转写、OpenAI 文本和 DeepSeek 文本分别绑定凭据；文本服务切换时不复制或共用另一服务商的密钥，自定义 API 地址的凭据按配置独立绑定。调用需要有效的 API 权限及网络，不将 ChatGPT 或 DeepSeek 网页登录当作 API 凭据。

删除会话同时移除其音频和数据库内容，操作前确认并核对目标目录属于应用管理的会话目录。

## 9. 错误处理

- 麦克风权限不足或设备移除：说明故障通道，允许重新选择；另一通道状态单独显示。
- 转写断线：本地录音继续，重连采用有界缓存；溢出或缺失区间明确标注，不能显示为完整转写。
- OpenAI 或 DeepSeek 超时、限流或服务错误：保留问题和已生成文本，显示服务商与可重试状态，转写照常进行。
- 磁盘或数据库写入失败：显示明确错误；录音不能可靠保存时停止录音，避免误报已保存。
- 关闭正在运行的会话：先询问是否结束，停止采集并落盘后关闭。

不承诺固定的端到端延迟。实际测试分别测量语音结束到最终转写、问题提取完成、首段回答出现的时间，界面展示处理状态。

## 10. 代码结构

- app：启动、路径、配置与依赖装配。
- ui：主窗口、设置、历史和复盘界面。
- audio：WASAPI 播放采集、Qt 麦克风采集、格式转换、文件写入。
- transcription：转写会话、事件解析与片段状态。
- ai：统一文本服务接口、OpenAI Responses 适配器、DeepSeek Chat Completions 适配器、SSE 解析、问题提取、回答队列和复盘服务。
- storage：SQLite 与会话文件管理。
- domain：对话、问题、生成任务及版本数据结构。

## 11. 验证与交付

先验证配套工具链能配置和编译 Qt Multimedia、SQL 与 WinHTTP 项目，再分别验证音频与 API。关键自动验证覆盖两家接口的分块 SSE 和结束状态解析、问题去重和修订关联、回答请求隔离、服务切换时的请求配置与凭据隔离、复盘来源引用及数据库恢复；使用明确的对话样例和模拟网络事件。

设备验收必须实际运行：戴耳机进行一段双方对话，核对两路音频、转写来源、暂停区间、问题提取、流式答案、结束落盘及重启后历史读取。使用各自有效凭据分别验收 OpenAI 和 DeepSeek；缺少某家凭据时明确报告该服务尚未联调。无 API Key 时可以验证界面、采集和模拟网络路径，不能声称真实转写或文本模型联调成功。

交付源码、CMake 配置、构建与使用说明及可运行的 Windows 包（工具链验证通过后制作）。发布目录不得包含用户录音、数据库或凭据。

## 12. 建议实施顺序

1. Qt 主窗口、设置、会话存储与历史记录。
2. 双路音频采集、设备选择、电平和 WAV 落盘。
3. 实时转写、片段显示和断线状态。
4. 问题提取、手动修正、OpenAI / DeepSeek 服务选择与流式参考答案。
5. 事后复盘、导出、关键验证与 Windows 打包。

第一版内置官方 OpenAI 和 DeepSeek 两种文本服务，默认选择 OpenAI，用户可切换；语音转写保持独立配置。使用其他服务前需核对其具体协议。
