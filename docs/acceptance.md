## 0.6.3 DeepSeek 连接关闭后的有界恢复（2026-10-23）

用户确认模型列表和“保存并测试连接”均报 Qt 2 / Connection closed。只读核对系统代理为 127.0.0.1:7897，Qt 请求使用系统代理配置；同一个官方 API、同样的产品请求头与虚构认证令牌，能够复现约5秒的 status=0 / RemoteHostClosedError，随后其他请求又能收到 HTTP 401。失败时 Qt 记录 socketStartedConnecting=true、encrypted=false、requestSent=false；成功时三项均为true。改变请求头或此前更换 TLS 后端均没有消除全部失败。证据证明本机可复现连接建立前关闭，不能据此确定关闭方是本地代理、上游路径还是服务端；没有将网页可用当作 API 连通证据，没有读取实际登录令牌来做联网测试。

模型列表的幂等 GET 在无 HTTP 状态的 RemoteHostClosedError 时，最多重试两次，间隔250/750ms。每次重试前校验仍是同一个账号会话；退出/更换账号后不再发送旧令牌。授权交换等 POST、HTTP 错误、证书错误和取消不进入此 GET 重试。

- 回环录音是所选播放设备的混音，可能包括其他软件的声音。
- 远端/麦克风是通道来源，不是声纹识别；时间位置为近似值。
- 自动提取、回答和复盘需要网络及正确的模型/API 权限。
- 实时问题识别与音量门限需要结合实际设备评估；可手动修正转写、问题并重试。
