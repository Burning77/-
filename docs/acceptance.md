## 0.6.3 DeepSeek 连接关闭后的有界恢复（2026-10-23）

用户确认模型列表和“保存并测试连接”均报 Qt 2 / Connection closed。只读核对系统代理为 127.0.0.1:7897，Qt 请求使用系统代理配置；同一个官方 API、同样的产品请求头与虚构认证令牌，能够复现约5秒的 status=0 / RemoteHostClosedError，随后其他请求又能收到 HTTP 401。失败时 Qt 记录 socketStartedConnecting=true、encrypted=false、requestSent=false；成功时三项均为true。改变请求头或此前更换 TLS 后端均没有消除全部失败。证据证明本机可复现连接建立前关闭，不能据此确定关闭方是本地代理、上游路径还是服务端；没有将网页可用当作 API 连通证据，没有读取实际登录令牌来做联网测试。

模型列表的幂等 GET 在无 HTTP 状态的 RemoteHostClosedError 时，最多重试两次，间隔250/750ms。每次重试前校验仍是同一个账号会话；退出/更换账号后不再发送旧令牌。授权交换等 POST、HTTP 错误、证书错误和取消不进入此 GET 重试。

DeepSeek 文本请求仅在观察到新建连接、尚未完成 TLS、未发出 requestSent、没有证书错误、没有响应字节及 HTTP 状态、无会话密码套件及加密连接标记时恢复，最多两次。因连接池可能不再发出 encrypted 信号，曾在同一个网络管理器建立 TLS 的来源也保守排除。已发出的 POST、部分回答、HTTP 错误、证书错误和未知/复用连接不自动重发。等待重试仍可取消，退出账号会取消等待并停止发送旧凭据。保留代理和证书校验，未改变系统代理、未关闭用户程序或录音。

重试恢复、次数上限、取消及退出等待的回归先失败后通过；测试使用隔离凭据和请求替身。新增注入请求由账号自己的网络管理器持有，避免测试替身晚于账号状态析构回调。Release 正式构建通过，完整 CTest 17/17、QtTest 198项通过，无失败或跳过。移除 Qt 开发工具 PATH，仅使用运行包 DLL 的 DeepSeek33项及文本请求17项通过。包含 TLS 已建立、请求已发送、连接复用/阶段未知、证书错误、部分回答、HTTP401和曾建立 TLS 来源的禁止重发覆盖。

## 实现调整

- 实时转写采用 Windows WinHTTP WebSocket。Qt WebSockets 的可选源码构建在本机工具链中异常终止，最终程序不依赖该组件。
- 中文源码路径下 Qt moc 无法创建生成文件，构建脚本使用专用英文源副本；源码仍在原工程目录。
- 业务实体以带稳定 ID 和来源字段的 JSON 记录存入 SQLite 索引表。
- 长会话按有界对话段生成分段复盘报告，附带相关问题；同一条超长发言也会拆段。报告没有二次生成的全局总结。

## 使用限制

- 回环录音是所选播放设备的混音，可能包括其他软件的声音。
- 远端/麦克风是通道来源，不是声纹识别；时间位置为近似值。
- 自动提取、回答和复盘需要网络及正确的模型/API 权限。
- 实时问题识别与音量门限需要结合实际设备评估；可手动修正转写、问题并重试。
